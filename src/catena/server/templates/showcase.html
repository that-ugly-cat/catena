plain words What this is for

The problem. A manuscript accumulates citations in three ways at once: some are proper Zotero fields, some are typed by hand as (Rosato et al., 2008), and some arrive from a co-author in a form nobody planned. Reconciling them means copying identifiers between a reference manager and a word processor, which is exactly where a bibliography goes quietly wrong — a mistyped DOI resolves to somebody else's paper and reads perfectly.

What catena does. It ties one paper to one Zotero collection, reads the citations a draft already contains, resolves them against real metadata, and writes them into the document as Zotero fields — the same fields the Word plugin makes. From then on the document is an ordinary Zotero document: changing the citation style is Document Preferences in Word, not something this tool has to be asked for.

What it refuses to do. It does not write prose. It does not invent an item when an identifier will not resolve — it says so and stops. It does not decide between two papers with the same title. And it never deletes anything from a library.

geek mode Same story, technical register

The field. A Zotero citation in Word is a field code carrying CSL-JSON and a URI that relinks it to the library item, plus two custom document properties holding the style. catena reads that format and writes it, and both halves were checked against a real manuscript, a generated fixture, a round trip through Word and a style change from Vancouver to APA.

The split. The server resolves and produces field codes; a local injector splices them into OOXML, knowing nothing about DOIs and holding no credential. The injector's difficulty is the document, not the bibliography: a marker scattered across five runs, a field that must stay inside the tracked insertion it belongs to or the sentence changes author, a comment anchor that must not be cut in half.

Access. catena has no credentials of its own towards Zotero. Every call runs with the caller's own key and reaches exactly what that person reaches; an account with no key configured reaches nothing at all. Writes are confined to one dedicated library, and there is no tool here that deletes an item or edits one that already exists.
